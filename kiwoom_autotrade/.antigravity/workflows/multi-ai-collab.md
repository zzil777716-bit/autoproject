# Workflow: Multi-AI Collaboration System (v1.1)

이 워크플로우는 6대 AI 페르소나(Gemini, GPT, Meta-AI, Manus, Copilot, Kimi)의 고유한 강점을 결합하여 최고 수준의 의사결정과 엔지니어링 산출물을 도출하는 오케스트레이션 절차입니다.

---

## 1. AI 페르소나 정의 및 전문 영역

1. **gemini (Google)**
   - **강점**: 논리, 구조화, 장기 계획, 대규모 코드 아키텍처, 형식 검증
   - **담당 영역**: 기술 설계, 시스템 아키텍처, 데이터 모델링, 복잡한 로직 구현

2. **gpt (OpenAI)**
   - **강점**: 창의성, 사용자 경험(UX), 인터랙션, 카피라이팅, 엣지 케이스 발굴
   - **담당 영역**: 서비스 기획, 비즈니스 모델, 브랜딩, UX/UI 흐름, 사용자 시나리오

3. **meta-ai (Meta)**
   - **강점**: 오픈소스 생태계, 효율성 및 가성비(토큰/연산 비용), 비판적 검증, 리스크 분석
   - **담당 영역**: 아키텍처 비판, 엣지 케이스 실패 분석, 보안/비용 리스크 진단, 오픈소스 대안 제시

4. **manus (Manus)**
   - **강점**: 실행력, 툴 사용(Tool-use), 자동화 파이프라인, 실제 구현 및 프로토타이핑
   - **담당 영역**: 실행 가능한 로드맵, 도구/API 연동 방안, 구체적 액션 아이템, 자동화 스크립트 설계

5. **copilot (GitHub / Microsoft)**
   - **강점**: IDE 개발자 경험(DX), GitHub 생태계(PR, Actions, Issues), CI/CD 파이프라인, 코딩 편의성
   - **담당 영역**: 워크플로우 자동화, GitHub PR 템플릿, Actions CI/CD 구축, 코드 리뷰, 단위 테스트

6. **kimi (Moonshot AI)**
   - **강점**: 초장문(Long-context) 컨텍스트 처리(2M+ 토큰), 방대한 기술 문서/논문/로그 전수 파싱, 손실 없는 정보 집약
   - **담당 영역**: 대용량 코드베이스 전수 검색, 대규모 RFC/논문 분석, 복잡한 멀티 파일 컨텍스트 통합

## 2. Core Rule - Supervisor Rotation System (감독자 순환 체계)

### Step 1: 감독자(Supervisor) 선정
작업의 성격에 따라 1명의 AI를 감독자로 선임합니다. (사용자 명시 지정 시 최우선 반영)
- **코딩 / 아키텍처**: `gemini`
- **기획 / 브랜딩 / 글쓰기 / 비즈니스**: `gpt`
- **검증 / 최적화 / 비판 / 보안 / 비용**: `meta-ai`
- **리서치 / 자동화 / 실행 / 도구 연동**: `manus`
- **IDE 환경 / CI-CD / GitHub 워크플로우**: `copilot`
- **대용량 문서 / 논문 분석 / 전체 레포 전수 탐색**: `kimi`

### Step 2: 작업 분해 (Task Breakdown)
선정된 감독자는 전체 목표를 핵심 하위 Task들로 구조화합니다.

### Step 3: 병렬 토론 (Parallel Debate)
감독자를 제외한 나머지 AI 페르소나 중 해당 작업에 최적화된 debater들을 선정하여 서브에이전트를 병렬 가동합니다.
- 각 토론자는 다음 경로에 자신의 분석 및 제안 보고서를 작성합니다:
  - `tasks/debate_[AI이름].md`

### Step 4: 감독자 취합 및 최종 결정 (Synthesis & Final Decision)
감독자는 토론 결과물을 모두 정독하고 상호 검증, 장단점 비교 분석을 거쳐 `tasks/final_result.md`에 최종 결과물을 도출합니다.
- **필수 포함 항목**:
  1. `[채택된 아이디어]`: 각 토론자의 제안 중 채택된 핵심 아이디어와 채택 이유
  2. `[기각된 아이디어와 이유]`: 검토되었으나 제외된 제안과 비판적 사유
  3. `[최종 실행 계획]`: 실질적으로 구현/적용할 구체적 액션 플랜 및 아키텍처/로드맵

### Step 5: 최종 보고 (User Reporting)
오케스트레이터는 사용자에게 다음 형식으로 최종 요약을 보고합니다:
```
감독자: [이름]
토론자: [이름들]
최종 결과 저장 경로: tasks/final_result.md
```
