## 0. 설계 목표

- **월요일 실전 가동 전략 (15분봉 3선 종가 유지 퀀트 검증 모델 - MFE 실증 하이브리드 세팅)**:
  1. **삼성전자(005930) [15분봉 3선 2봉 연속 종가 유지 전략 (15M 3-Lines Sustained Close)]**:
     - 15분봉 3선(20선, VWAP20선, 일목 전환선 13) 위 2봉 연속 종가 안착 확인 시 진입
     - 손익비: SL -0.90%, TP1 +1.50%(본절 스탑 전환), TP2 +2.80%(트레일링 스탑)
     - 1개년 검증 성과: **승률 52.5%, Profit Factor 1.56, MDD -5.11%, 누적수익률 +49.39%**
  2. **SK하이닉스(000660) [15분봉 3선 지지 + 3분봉 5EMA/거래량 점화 전략 (15M Sustained & 3M Micro-Ignition)]**:
     - 15분봉: 3선(20선, VWAP20, 전환선 13) 위 2봉 연속 종가 유지 확인
     - 03분봉: 5 EMA 상향 돌파 & 거래량 1.35배 폭발(RVOL $\ge$ 1.35) & 체결강도 105%↑
     - 손익비: SL -0.90%, TP1 +1.50%(본절 스탑 전환), TP2 +2.80% 트레일링 & 3선 붕괴 시 동적 청산
     - 1개년 검증 성과: **Profit Factor 2.10 (수익비 최고), MDD -6.81%**
- **시스템 확장성 및 안정성 목표**:
  - **Transactional Outbox (SQLite WAL)**: 주문/체결/킬스위치 이벤트의 무손실 내구성 보장.
  - **주문 직전 JIT 킬스위치 이중 확인**: 이벤트 유실 시에도 주문 전송 직전 0.001초 전에 차단.
  - **비동기 핫패스 분리**: 로깅/클라우드 업로드 I/O가 주문 실행 속도에 전혀 영향을 주지 않음.

## 1. 전체 아키텍처 개요

```
                          ┌─────────────────────────┐
                          │   전략 SDK (공통 인터페이스)   │
                          │  백테스트 / 실시간 동일 코드    │
                          └─────────────┬────────────┘
                                        │
        ┌───────────────┬──────────────┼──────────────┬───────────────┐
        │               │              │              │               │
   [시세 수집기]     [정제/저장 워커]   [전략 워커 N개]   [리스크 엔진]   [Reconciliation 워커]
   (수집 전용)      (정제→시계열DB)   (계좌/전략별 격리)  (로컬+글로벌)   (주문 상태 확인)
        │               │              │              │               │
        └──────┬────────┴──────┬───────┴──────┬───────┴───────┬───────┘
               │               │              │               │
       [메시지 브로커 / 이벤트 버스]  (내구성 보장, ACK 기반 신호 파이프라인)
               │
       ┌───────┴────────┐
       │  브로커 어댑터    │  (계좌별 인스턴스, 키움 API = Windows COM 격리)
       └───────┬────────┘
               │
       ┌───────┴────────┐
       │   증권사 (키움)   │
       └────────────────┘

   [API 서버 / 런처: CQRS]
   ├─ Command(쓰기): 주문/전략 시작·중지 → 메시지 브로커로 발행
   └─ Query(읽기): 시세/포지션/로그 조회 → 읽기 전용 DB(Read Replica)

   [저장소 레이어]
   ├─ 시계열DB (SQLite / TimescaleDB): 분봉/일봉 OHLCV, 기술적 지표
   ├─ 데이터 레이크 (SQLite / Parquet): 5초 스냅샷, Near-Miss 탈락 로그
   ├─ 매매 일지 & 엑셀 (SQLite, XLSX): MFE/MAE 매매 저널, 1달 단위 HTS 테마/대장주 통합 엑셀
   └─ 클라우드 미러 (Google Drive): G:\내 드라이브\Antigravity 자동 백업

   [킬 스위치]
   └─ 정책(룰) 엔진: JSON 설정파일(kill_switch_rules.json) 기반 룰 → 실시간 무중단 갱신
```

## 2. 컴포넌트별 상세 설계

### 2.1 시세 데이터 저장소 분리
- **시계열DB (`storage/timeseries_db.py`)**: 3M/5M/15M 분봉 OHLCV, 기술적 지표 계산용 데이터
- **데이터 레이크 (`storage/data_lake.py`)**: 5초 주기 호가/수급 스냅샷, MFE/MAE Excursion 아카이브
- **트랜잭션 DB (`storage/trade_journal.sqlite`)**: 계좌 주문, 포지션 라이프사이클, 손익 데이터 전담

### 2.2 전략 워커: 계좌/전략 단위 독립 인스턴스
- **삼성전자 MTF-Squeeze 워커 (`workers/worker_samsung_squeeze.py`)**
- **SK하이닉스 삼중스크린 워커 (`workers/worker_hynix_pullback.py`)**
- 한 전략/계좌에서 예외가 발생해도 다른 워커에 영향이 없도록 프로세스 단위 완전 격리

### 2.3 브로커 어댑터: 계좌별 인스턴스화
- `BrokerAdapter(ABC)` 표준 인터페이스를 정의하고, 키움 COM API를 `KiwoomAdapter`로 캡슐화
- 향후 타 증권사(한국투자, 이베스트) REST API 추가 시 어댑터만 추가하면 기존 전략 100% 재사용

### 2.4 Reconciliation(주문 상태 동기화) 워커
- `workers/reconciliation_worker.py`: 미체결/부분체결 주문을 실시간 감시하여 계좌 실제 잔고와 시스템 상태 동기화

### 2.5 리스크 엔진: 로컬 / 글로벌 분리
- **로컬 리스크 (`risk_engine/local_risk.py`)**: 1회 1주 고정 주문, -0.90% 손절선, MFE/MAE 실시간 트래킹 (인메모리 초고속 1차 방어)
- **글로벌 리스크 (`risk_engine/global_risk.py`)**: 계좌 일일 손실 한도, 연속 손실 쿨다운, 킬 스위치 정책

### 2.6 킬 스위치: JSON 정책 룰 기반 (`config/kill_switch_rules.json`)
- 코드 수정 및 재배포 없이 일일 최대 손실액, 에러 임계치 룰을 동적으로 적용

### 2.7 전략 SDK: 백테스트 = 실전 동일 코드
- `sdk/base_strategy.py`, `sdk/data_feeds.py`로 데이터 피드를 추상화하여 백테스트 코드가 실전에 즉시 가동
